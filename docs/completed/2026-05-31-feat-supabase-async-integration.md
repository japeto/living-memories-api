## Summary
Wire the FastAPI backend to Supabase using the official `supabase` Python SDK
with **native async** support (`acreate_client` / `AsyncClient`). This delivers
the shared persistence/storage layer that every vertical slice
(`auth`, `audio_management`, `ai_analysis`) will depend on, exposed through a
single injectable dependency. No business feature is implemented here — this is
the foundation the repositories will build on.

## Business Logic / Change Description

### 1. Client lifecycle (`app/core/supabase.py`)
The SDK's `AsyncClient` wraps a long-lived `httpx.AsyncClient`. Creating one per
request wastes connection pooling, so we create **one** at app startup and reuse
it. Pattern:

```python
from supabase import acreate_client, AsyncClient
from supabase.lib.client_options import AsyncClientOptions

# Created in lifespan, stored on app.state.supabase
client = await acreate_client(
    settings.SUPABASE_URL,
    settings.SUPABASE_KEY,  # anon key by default
    options=AsyncClientOptions(
        postgrest_client_timeout=settings.SUPABASE_TIMEOUT,
        storage_client_timeout=settings.SUPABASE_TIMEOUT,
        schema="public",
    ),
)
```

The dependency reads the client off `request.app.state` (no global mutable
singleton, no re-creation per request):

```python
def get_supabase(request: Request) -> AsyncClient:
    return request.app.state.supabase

SupabaseDep = Annotated[AsyncClient, Depends(get_supabase)]
```

### 2. Lifespan wiring (`main.py`)
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    app.state.supabase = await init_supabase()
    yield
    await close_supabase(app.state.supabase)

app = FastAPI(..., lifespan=lifespan)
```

### 3. Flow for the reference slice
`router.py` (injects `AuthServiceDep`, no logic) → `service.py` (business rules,
raises `HTTPException`) → `repository.py` (only place that touches
`AsyncClient`, returns plain dicts/models). This is the contract every future
slice copies. Layer boundary enforced: the router never imports the repository.

### 4. Error handling
Repository wraps SDK calls; on `APIError`/transport failure the service raises
`HTTPException(status_code=503, detail="database unavailable")` for the health
check and `401` for failed auth. No SDK exception leaks raw to the client.

## External Integrations
**Supabase (PostgreSQL + Storage), official `supabase` SDK, async API.**
- Auth/anon key (`SUPABASE_KEY`) for normal request-scoped access (respects RLS).
- Service-role key (`SUPABASE_SERVICE_ROLE_KEY`) **server-side only**, for
  privileged operations (e.g. background AI writes). Never returned in a
  response, never logged.
- Storage bucket (`SUPABASE_STORAGE_BUCKET`) for the audio files
  (`audio_management` will use `await client.storage.from_(bucket).upload(...)`).
- Realtime (future) requires this same async client.

## Remaining Risk Alerts
1. **RLS** — With the anon key, every table needs Row Level Security policies or
   reads/writes silently return nothing / fail. Schema + RLS authoring is a
   prerequisite for the *feature* tasks, not this wiring task, but it must exist
   before the reference repository returns real data. PIN hashing (decision #1)
   means writes to `users` likely use the **service-role key** server-side.
2. **Version pin** — `supabase` releases frequently. Floor is `>=2.15.0` for
   native async; lm_developer pins the exact resolved latest via `uv add`
   (I will not assert a version I cannot verify here).
3. **Secrets** — `.env` must hold real keys locally and be git-ignored; CI/deploy
   needs the same vars. Confirm `.env` is in `.gitignore` before committing.
4. **No live project to test against** — `/health/db` acceptance assumes a real
   Supabase URL/key in `.env`. If none exists yet, lm_qa mocks the client and the
   live check is deferred.
